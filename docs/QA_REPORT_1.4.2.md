## 已复现并修复的问题

| 范围 | 根因与处理 |
| --- | --- |
| 备注输入中断 | 自动保存复用显式保存入口，主动提交并销毁编辑控件。后台保存现在等待编辑结束，覆盖备注、紧凑卡片、参数表、分组名和输入法预编辑状态。 |
| 编辑字号过小 | 应用级 `QWidget` 样式中的 13px 覆盖了编辑框 `setFont()`。备注编辑样式显式使用与绘制相同的缩放字号，并同步文档字体。 |
| CSV 中文乱码 | 导出使用无 BOM 的 UTF-8，Windows 表格软件可能按本地编码打开。所有导出入口统一使用 UTF-8 BOM。 |
| 刚输入的卡片内容漏存 | 提交待编辑内容的入口只处理独立备注，遗漏紧凑卡片。现已覆盖未回车、未失焦的卡片字段。 |
| 刷新覆盖草稿 | 表单每次刷新都将整个模型重新写入控件。现在对比上次呈现的模型值，其他字段刷新时保留草稿、光标和输入状态。 |
| 多字段保存丢失后续输入 | 逐字段提交时，前一个字段触发刷新或表单重建，后续字段被覆盖。现在先读取全部草稿，再通过控制器整体提交。 |
| 属性绑定残留 | 取消选择未清空旧节点绑定；提交目标依赖当前选中项。现在将草稿交给原绑定节点，再切换或清空属性表单。 |
| 撤销后误判已保存 | 仅比较撤销栈数字索引，相同索引可能对应另一条编辑分支。改用 Qt 的保存标记，并在恢复文档会话时保留该标记。 |
| 数字输入中间态异常 | 直接把 `-`、`.` 等输入转为数字会抛错，可空整数还可能被错误清空。中间态不提交，整数校验也不再接受小数。 |
| 批量 CSV 导出破坏旧文件 | 直接打开目标写入会提前截断文件，同时行生成可能修改原模型。统一为副本转换、临时文件和原子替换。 |
| 旧表头模板导致导出失败 | 非 UTF-8 模板的解码错误未处理。无法读取的模板现在回退到 schema 标准表头。 |
| 更新发布失败无法重试 | 清理旧发布早于切换最新版本，切换失败后还留下同版本目录。现在先完成版本切换，失败时恢复原发布并清理本次目录。 |
| 缓存占用阻断发布 | 删除旧缓存的权限或占用错误被当作发布失败。新版本发布完成后再尝试清理，失败的旧缓存留待后续重试。 |
| 成品无法启动 | PyInstaller 从外部工具的 PATH 收集到不兼容的 ICU DLL，Qt 所需的函数不存在。构建 PATH 现限定为锁定环境和 Windows 系统目录；签名前必须通过实际 EXE 启动、JSON 打开和单实例文件转交检查。 |
