# 工作区刷新、启动性能与版本历史

## 行为

- `Ctrl+F` 使用左侧原生 `QLineEdit`，移除 `Qt.Popup` 搜索窗；字段搜索与节点目录合并。
- `QFileSystemWatcher` 同时监听当前文件和父目录，350 ms 合并写入通知，原子替换后
  重新注册监听。每 1.5 秒仅检查当前文件的属性作为漏通知回退；未变化时不读 JSON。
  属性变化后读取一次内容指纹，内容未变则不重载；脏文档的同一次外部更新也不会反复读取。
- 干净且未输入时先完整解析新文件，再替换当前文档并清空旧撤销栈，保留视角与有效选中节点。
  未保存修改、中文预编辑、拖动、半份 JSON 和删除都会保留当前内容。覆盖保存也在底层检查
  磁盘基线，因此快捷键、自动保存、工具调用等入口都不会无提示覆盖已检测到的外部修改。
- 文件列表跳过 `.git`、`.svn`、`.venv`、`.tools`、`.uv-cache`、`.uv-python`、
  `__pycache__`、`node_modules`、`build`、`dist` 这些依赖/版本控制/构建目录。
  同一份 JSON 的识别及角色名读取共用按文件属性失效的缓存。

## 内嵌历史格式

图表仍写为 `format_version: 5`，可选 `history.version: 1`。`revisions` 按旧到新排列，
每项包含随机 ID、UTC 保存时间、文档作者、标签、内容 SHA-256，以及回退到上一版的
`reverse` 增量。增量路径使用 JSON 键数组，区分键不存在和 JSON null。当前正文作为
历史链的最新内容，不额外复制完整图表；节点、分组、图片、笔迹按稳定 ID 索引后逐字段比较，
集合顺序单独保存。未变化图片不进入增量。视角和兼容展示模式不产生历史版本。

读取只检查历史结构和大小，选择旧版本时才回放并逐版本校验。保存成功替换磁盘文件后才
推进内存历史；失败时保留原历史与原文件。最多保留 50 版、512 KiB（包括 JSON 缩进），
超限删除最旧增量并把新的最早版本标为保留起点。单次变化超出容量时，只保留最新基线。

v1-v5 的旧图表无需预处理，首次修改并保存时记录打开基线及当前版本。没有历史时无法
凭空恢复以前的修改，较早版本继续从 SVN 查询。旧编辑器可以读取图表正文，但可能在保存时
移除可选历史。未知版本的、大小在上限内的历史扩展原样保留，不解释或追加；无效/过大
历史扩展不阻止图表打开。手工修改正文却保留旧历史时，内容指纹会阻止错误回放，下次保存
重新建立基线。历史预览始终使用独立场景，不参与当前图表的撤销或保存。

## 验证

在本机同一源码工作区，以隔离设置、不恢复上次图表、开启 cProfile 的窗口初始化测量：
改动前约 1.56 s，其中目录扫描约 1.43 s；改动后约 0.08 s，其中目录扫描约 0.01 s。
这些数字描述源码窗口初始化，不包含解释器导入、打包 EXE、磁盘冷缓存或大型图表恢复时间。

回归覆盖中文输入事件、连续原子替换的真实文件监听、未提交输入与脏文档冲突保护、
半写文件恢复、非当前文件缓存失效、无变化时无 JSON 读取、历史回放/裁剪/损坏、保存失败、
旧格式兼容及图表预览的只读性。原生 Windows 字体环境另行渲染历史窗口检查布局。

完整运行了 22 个测试模块，并在最后一次保存边界修正后重跑历史、工作区刷新与工具服务模块。

`svnadmin` 跳过；SVN 命令参数、解析和错误处理的自动测试通过。尚未构建或安装新的发布包。
