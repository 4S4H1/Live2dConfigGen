# 工作区刷新、启动性能与版本历史

## 行为

- `Ctrl+F` 使用左侧原生 `QLineEdit`，移除 `Qt.Popup` 搜索窗；字段搜索与节点目录合并。
- `QFileSystemWatcher` 同时监听当前文件和父目录，350 ms 合并写入通知，原子替换后
  重新注册监听。每 1.5 秒仅检查当前文件的属性作为漏通知回退；未变化时不读 JSON。
  属性变化后读取一次内容指纹，内容未变则不重载；脏文档的同一次外部更新也不会反复读取。
- 干净且未输入时先完整解析新文件，再替换当前文档并清空旧撤销栈，保留视角与有效选中节点。
  未保存修改、中文预编辑、拖动、半份 JSON 和删除都会保留当前内容。覆盖保存也在底层检查
  磁盘基线，因此快捷键、自动保存、工具调用等入口都不会无提示覆盖已检测到的外部修改。
- 文件列表跳过 `.git`、`.svn`、`.venv`、`.tools`、`.uv-cache`、`.uv-python`、
  `__pycache__`、`node_modules`、`build`、`dist` 这些依赖/版本控制/构建目录。
  同一份 JSON 的识别及角色名读取共用按文件属性失效的缓存。

## SVN 历史版本

“版本历史”统一查询当前文件的 SVN 提交记录。比较两端均为仓库中的数值 revision，
默认选择该文件最近两次提交；此前一次是文件日志中的上一条提交，不是仓库全局的 `r-1`。
也可选择任意两个已提交版本，并继续分页加载更早记录。只有零次或一次提交时明确提示
无法比较，不以本地文件或未保存的编辑内容充当另一个版本。

`svn info` 仅用于解析仓库路径与历史来源；`svn log` 和 `svn cat -r` 从仓库读取记录与正文，
比较不会保存 JSON、创建临时 diff 文件、修改编辑器文档或撤销栈。读取失败、取消、
版本 JSON 损坏时保留当前编辑内容，不替换为其他来源。窗口缓存最多 12 份已读取版本。

图表中以绿色、红色虚线、金色标记新增、删除、修改，右侧逐字段显示前后值。
正式图、计划图、笔迹、参考图片及监听器内部字段均参与比较；画布视角和旧内嵌历史
不参与比较。初次显示后按真实视口适配图表，大图低倍率下也能立即滚轮缩放和拖动平移。

JSON 保存不再生成或追加内嵌 `history`，没有历史字段的旧文件继续不含该字段。
已有的字典型 `history` 仅作为不透明兼容数据原样读写，包括旧版或未来版本的内容；
不会校验、回放或续写其中的增量。非字典历史字段不影响图表正文读取。由此保留原文件
中的旧数据，同时去除保存时构造整图快照、计算历史增量和历史回放的代码。

## 验证

在本机同一源码工作区，以隔离设置、不恢复上次图表、开启 cProfile 的窗口初始化测量：
改动前约 1.56 s，其中目录扫描约 1.43 s；改动后约 0.08 s，其中目录扫描约 0.01 s。
这些数字描述源码窗口初始化，不包含解释器导入、打包 EXE、磁盘冷缓存或大型图表恢复时间。

回归覆盖中文输入事件、连续原子替换的真实文件监听、未提交输入与脏文档冲突保护、
半写文件恢复、非当前文件缓存失效、无变化时无 JSON 读取、保存失败、旧格式兼容、
旧历史字段原样保留、保存不生成历史，以及图表预览的只读性。

历史窗口专门覆盖真实 Qt 滚轮和拖动事件：大图首次显示、显示全图后、可见窗口内切换
版本时均无需先选择节点；SVN 窗口测试覆盖仅提交版本的选择、默认上一条文件提交、
分页、任意两个版本、缓存淘汰、取消及损坏版本。真实 SVN 仓库集成用例在环境缺少
`svn` 或 `svnadmin` 时跳过，命令参数、解析和错误处理另有独立测试。
