# 监听器子蓝图

> 发布状态：功能仍在完善，当前版本已屏蔽新建与所有子图 UI 入口。
> 下述操作说明供开发参考；已有 v6 数据继续保留，普通图使用不受影响。

监听器由触发源、连接器、参数操作、参数状态和结果组件组成。主图中的「监听器」代表一个子蓝图；双击进入内部画布，拖动端口连线，在右侧编辑组件属性。内部编辑使用主文档的撤销栈，保存时仍保存在同一个 JSON 中。

已有交互节点也可以带监听器。例如某个触区本身维持点击开关逻辑，另一个动作播放后把它的参数归零；原有 `action_trigger` 等交互配置会保留。旧的 `listener_data` 可导入为子蓝图，不能无损转换的内容会报错并保留原文。

## 组件与执行含义

| 组件 | 含义 | 连线 |
| --- | --- | --- |
| 动作播放 | 匹配动作名称，区分大小写 | 事件输出 |
| 触区点击 | 匹配触区名称，如 `TouchDrag1`，区分大小写 | 事件输出 |
| 待机切换 | 匹配非负待机编号，包含 `0` | 事件输出 |
| 任一事件 | 同一种事件中的任一个匹配即可 | 多个事件输入、一个事件输出 |
| 累加参数 | 在当前目标值上加数值，允许负数和小数 | 一个事件输入、参数变化输出 |
| 设置参数 | 将目标值设为指定数值 | 一个事件输入、参数变化输出 |
| 监听参数 | 保存本监听器的初始值、上下限和保存偏好 | 多个参数变化输入、数值输出 |
| 区间切换待机 | 最终数值落在区间内时切换待机 | 一个数值输入 |

每个子蓝图只有一个「监听参数」，其上游触发源必须属于同一种事件类型。多个动作名可以通过一个触发源的逗号/换行列表，也可以通过「任一事件」组合。一个规则的列表中即使命中重复名称，该规则也只执行一次；多个规则同时匹配则依次执行。

参数操作按「执行顺序」从小到大排列；顺序相同时保持组件在文档中的先后顺序。每次操作后，运行时按宿主的方向限制、绝对值设置和参数上下限修正目标值。动作队列位置默认是 `1`；填 `0` 或负数表示保持原位置。参数保存开关导出为游戏已有的 `save_parameter`：勾选为 `0`，关闭为 `-1`。

区间含下限、不含上限，例如 `[0, 1)`。所有参数操作执行完后，再计算待机结果。没有区间匹配时维持原待机；多个区间重叠时，顺序最后的匹配项生效。编辑器对重叠给出提示。待机结果再次触发自己的待机事件时也会提示可能发生反馈，需要检查逻辑。

空的 L2D 参数名允许保留内部状态，不会写入模型参数，编辑器对此给出提示。未连通组件、错误端口、循环连线、混用事件类型、不支持的组件、非法数值会阻止导出；可继续保存未完成的 JSON 草稿。未实现「并且」「延迟」「任意脚本」或跨事件种类合并，因为已有游戏解释器不能表达这些逻辑。

## 与游戏配置的关系

子蓝图编译为现有 `ship_l2d` 行中的 Lua 表文本，CSV 不增加自定义运行时字段。例如：

```lua
{type=1,change={{1,{'touch_drag1'},1},{2,{'touch_idle1'},0}},apply={1,{{0,1,0},{1,2,3}}}}
```

这里 `type=1/2/3` 分别对应动作播放、触区点击和待机切换；`change` 每项依次为操作类型、匹配事件列表、数值和可选队列位置；操作类型 `1` 为累加、`2` 为赋值。`apply={1,...}` 为参数区间到待机编号的映射。

独立监听器使用 `action_trigger={type=7}`、无触区、无拖拽偏移和无陀螺仪输入的配置外壳；这避免内部参数被它自己的鼠标拖拽覆盖。附加到旧交互时保留其原触发方式、平滑和方向配置。

运行时还有两个需要注意的已有行为：`action_trigger.change_focus=false` 会推迟参数赋值到动作结束；在这种模式下，同次事件的多个累加规则会读取尚未更新的目标值。`action_trigger_active.idle` 若已配置，会优先于 `listener_data.apply` 中传递的待机值。子蓝图编辑不会擅自改变这两项宿主设置。

「触区点击」通过游戏点击交互的动作处理回调发出，不能等同于任意鼠标按下。事件名按原大小写精确匹配。监听器参与该 L2D 对象的初始化、逐帧参数更新、保存和销毁；不需要额外的全局订阅生命周期。`revert=-1` 且未禁止保存时，参数按交互 ID、皮肤和舰船保存并在加载时恢复。独立监听器默认保持数值，是否跨加载保留由保存开关控制。

## JSON、历史和旧文件

含子蓝图的文档使用 `format_version=6`，子蓝图放在宿主节点的 `listener_graph` 中。没有子蓝图的文档继续保存为 v5；当前版本可以打开原有旧 JSON，旧 `listener_data` 文本在主动导入之前保持原样。较旧编辑器不能编辑新子蓝图，不应使用它们覆盖 v6 文件。

每个子蓝图的组件和连线使用独立 ID 存储，另存顺序列表。内部字段变化进入现有历史增量，不为每次修改复制整张子蓝图。子蓝图的缩放和平移不会增加历史版本；组件移动和连线变化会记录。历史仍受最近 50 版、512 KiB 的总限制。

在版本历史或 SVN 对比中，子蓝图变化会标记所属宿主节点，变化列表能显示具体组件字段。选中后可分别打开「修改前」「修改后」的只读子蓝图；双击宿主默认查看修改后，已删除的宿主查看修改前。历史窗口使用独立文档副本，不能修改当前编辑内容。

单个子蓝图还限制为 512 个组件、2048 条连线和 2 MiB，以避免误输入生成无限体积。旧文本导入只解析数值、字符串和 Lua 表字面量，不执行任何 Lua 表达式或函数。
